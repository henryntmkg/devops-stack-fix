# DevOps Stack Troubleshooting & Optimization

Решение тестового задания по диагностике, устранению багов и оптимизации контейнеризованного сервиса (Nginx + PHP-FPM 8.4 + MySQL + Redis).

## 📌 Найденные проблемы и узкие места

1. **Ограничение процессов PHP-FPM (`pm.max_children = 5`):**
   * **Проблема:** При параллельной нагрузке (50 клиентов) воркеры мгновенно исчерпывались. Запросы вставали в очередь FastCGI, что приводило к задержкам до 4.5 сек и ошибкам `500 Internal Server Error`.
   * **Решение:** Значение `pm.max_children` увеличено до `50` в `www.conf`.

2. **Некорректная логика кэширования и блокировок в PHP (`getItems`):**
   * **Проблема:** Искусственная задержка `usleep(2500000)` в сочетании со слишком короткой паузой ожидания замка (`usleep(200000)`) выбивала параллельные запросы в `RuntimeException('cache is busy')` (HTTP 500).
   * **Решение:** Убрана искусственная задержка, реализован устойчивый цикл ожидания кэша (spin-lock).

3. **Persistent-соединения PDO (`PDO::ATTR_PERSISTENT`):**
   * **Проблема:** Риск исчерпания пула соединений MySQL и отвалов по `wait_timeout`.
   * **Решение:** Флаг отключён для предотвращения забития пула и мёртвых сокетов.

## 🚀 Быстрый запуск

Запуск оптимизированного сервиса одной командой:

```bash
docker compose up -d --build
```

Сервис будет доступен по адресу: http://localhost:8080
    GET /health — Базовая проверка сервиса
    GET /diag — Диагностика зависимостей (DB/Redis)
    GET /items — Получение списка записей (с кэшированием)
    POST /add — Добавление новой записи
